# ziwei · 紫微斗数

插件版本 `2.0.0+iztro.2.6.3`。`ZiweiPlugin` 实现 `OraclePlugin`；由 `SkyPlugins.all` 注册。算法版本与旧民用钟面排盘分开，历史结果不会被重写，也不能作为新口径结果直接复用。

## 接口与输入

`calculate(OracleInput) async throws -> OracleResult`

必须有确认过的公历出生日期、出生时间、出生地 IANA 时区、有效出生地坐标和排盘性别（男 / 女）。`birthDate` 是已由表单按出生地历史时区解析的绝对时刻。插件调用公共 `TrueSolarClock.birth(profile:)`，用出生经度与 NOAA/Meeus 均时差取得独立的真太阳钟面；完整太阳年月日和小时索引一起传给 iztro，原始 `Date` 不被修改。

原始出生日期支持 1900–2100 年；校正后可以跨到 1899 或 2101，不会钳制回原范围。如果本地紫微内核不能处理该校正后的边界，返回明确的 `unavailable`，不改回民用时刻排盘。23 点为晚子时（索引 12），0 点为早子时（索引 0），其余按两小时划分。

出生时辰、性别、日期、时区或出生地点标记为不确定时，返回 `unavailable`，不猜测时辰，不用默认时刻生成唯一命盘。出生地沿用公共出生坐标规则：可从明确选择且未撤回的区县目录补回整对缺失的旧坐标；不根据自由地名、当前所在地或区县目录覆盖部分、无效或已撤回的坐标。

问事时刻只用于当前已展示的流年、虚岁与大限查询：保留真实 `castingDate` 在 `currentTimeZoneID` 下的民用日期与时辰，不作目标真太阳时校正，也不额外要求当前地点坐标。当前时区无效时沿用原有的出生时区回退。结果明确区分“本命真太阳时”和“运限民用时”，不声称运限已作太阳时校正。

## 本地实现

`Resources/Sky/iztro.bundle.js` 内置 iztro 2.6.3 及锁定依赖，通过系统 JavaScriptCore 执行。脚本没有原生网络桥接、fetch、XMLHttpRequest 或远程资源。设备不需要 Node、npm、Python、WebView 或本地 HTTP 服务。

配置固定为 `yearDivide=normal`、`horoscopeDivide=normal`、`dayDivide=forward`、`fixLeap=true`、`zh-CN`。闰月前后半月调整。本命采用太阳钟面的零点日期；晚子时的内部排盘处理仍交给 iztro，Swift 调用前不另加一天，避免重复换日。这是本项目明确选择的口径，不代表所有紫微流派都要求真太阳时。需要其他流派时应增加明确配置并验证。

历史夏令时已经包含在原始绝对时刻与出生地时区中，校正不再手动减一小时。代表性地区坐标可能影响临近时辰、换日的结果，需核对实际出生地点和原始钟表记录。西方占星继续使用真实绝对时刻及其既有恒星时、经度计算，不接收紫微的太阳钟面 `Date`。

## 输出

原始钟表时间及 IANA 时区、真太阳时、计算经度、经度及时制校正、均时差、总校正、本命太阳时辰、运限民用查询时间，以及十二宫、主辅星与亮度、生年四化、大限区间、问事流年四化、问事虚岁。`evidence` 只对四化做显式符号规则映射：禄偏资源、权偏责任主导、科偏条理与可见度、忌偏牵挂与反复。该映射不构成经验预测概率，不能单星断事件。原始宫位独立保存在 `rows` 中，供数据页查看；AI 应同时读取 limitations。
