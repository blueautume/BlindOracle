# BlindOracle 架构与落地说明

## 1. 边界

本地插件负责数值、历法、起卦和固定规则。AI 是可替换的语言服务，负责准备调用计划、对话、资料澄清和解读整合，不能代算命盘。位置、时区、城市和资料不确定性都作为输入，而非由模型暗中猜测。

本地「服务」采用同进程协议调用，不开启 HTTP 端口。iOS 的插件是随 App 签名发布的模块；新增原生算法通过应用更新交付，不下载执行未经签名的代码。

## 2. 插件契约

`OraclePlugin` 提供两项能力：

```swift
var descriptor: OraclePluginDescriptor { get }
func calculate(_ input: OracleInput) async throws -> OracleResult
```

descriptor 声明版本、必填/选填资料、适用问题、输出说明、边界、来源与许可，直接组成 AI 的工具目录。每个插件另有 Markdown 文档，位于 `Documentation/Plugins`。调用结果有 complete、partial、unavailable、failed 四种状态；每条规则证据包括语义倾向与强度，它们是规则元数据，不是现实概率。

注册表对计划进行方法白名单约束，并合并 descriptor 的必填字段；AI 无法用计划删除本地要求。当前每个插件暴露 `calculate` 一个入口，内部可按输入完整性返回局部能力。后续增加本命/流年等子接口时，可在 descriptor 扩充 operation 列表与相应参数类型。

扩展步骤：为 `OracleMethod` 增加稳定 ID；新增 conforming 插件和文档；加入 `NativePlugins.all` 或 `SkyPlugins.all`；增加可重复参考例和未知资料测试；重新生成工程。结果与持久化统一使用 Codable 模型，既有 UI 无需增加专属页面。

## 3. 执行状态机

`idle → planning → awaitingIntake → calculating → synthesizing → idle`。

问题先落盘。计划生成后显示问事笺：已有资料自动填入，时间/时区来自设备，位置按需授权获取。出生日期、时刻、出生地、时区、姓名都支持未知。当前地点不会替代出生地；为他人问时建立独立 UUID 的档案，也可以选用已保存的他人资料。

确认后的 `OracleInput` 包含不可变资料快照、起问时刻、随机种子和可选报数。种子保证实际摇卦可复查；不以随机数伪造其他排盘。插件在后台异步逐项调用，逐项保存结果。串行调度与历法缓存锁避免第三方共享状态竞争；UI 只显示完成数量和执行摘要。

每次任务有 operation UUID。停止会取消任务；旧网络增量和旧计算回调无法写入新对话。已完成的本地结果保留，可以重新请求 AI 解读。新对话保留档案和历史推演，也将原聊天收入历史侧栏；切换历史会话恢复其原文、摘要与待填问事笺，并取消之前的任务。新对话不会默认引用上一卷的结果。

## 4. AI 与流式输出

使用 DeepSeek HTTPS chat/completions。计划为 JSON，方法和资料字段被本地白名单解析；模型名通过设置可替换。汇总为流式 JSON，正文是首个 text 字段；增量 JSON 字符串解析器处理转义、分片和 Unicode，只把正文送到聊天 UI。接收 SSE 的 content，内部 reasoning_content 不解码、不展示、不保存。

折叠的一行思考区域展示应用层执行摘要（听取问题、核对资料、本地推演数量、整理线索），展开也只有这些步骤状态。它不展示模型内部思维链。

AI 汇总仅接收 complete/partial 结果；partial 限制必须保留，failed/unavailable 不得作为证据。约四百字是提示词目标，用户追问可详细展开。没有连接时展示明确标识的本地规则摘要；结果不丢失。

## 5. 分歧与偏好

提示词要求将轻微分歧合并，只在明显分歧时输出恰好两个处境选项。解析器验证选项 ID、实际支持者、白名单及两组互斥性；无效分组不展示为可学习选择。

初始九个权重相等。每份推演只能产生一次偏好反馈；支持选择的权重乘 exp(0.035)，相反组乘 exp(-0.035)，未涉及者不作直接奖惩，再投影到归一化有界区间 4%–25%。一次反馈通常只改变不到一个百分点。此数值描述用户觉得更贴近的解释，不能称为方法准确率。已选择的分歧选项不会因重新解读而被悄悄替换。

## 6. 本地存储与上下文

Application Support/BlindOracle：profiles.json（永久资料）、readings.json（每次快照与逐项结果）、preferences.json（全局个人偏好）、conversation-history.json（版本化会话列表与当前 ID）。每段聊天拥有自己的消息、摘要与待填问事笺；conversation.json、context.json、pending-intake.json 继续作为兼容快照保存。

首次升级会迁移旧 conversation-<timestamp>.json 归档，按消息 UUID 去重。版本化历史文件一旦存在即为权威来源，即使删光聊天也不会重新导入旧档案。长按删除只移除该聊天，不联动删除独立推演、基础档案或个人偏好。聊天内「翻看数据」以消息的 runID 打开专属结果 Sheet，展示该次每个方法原始返回，不跳转全局数据总览。

JSON 原子写入并启用首次解锁后文件保护；目录排除自动云备份。应用运行时将凭据保存于 ThisDeviceOnly 钥匙串，不进入资料 JSON、对话、日志或导出。用户主动导出的备份包含个人资料与推演，不包含密钥。

压缩阈值约 32k 估算 token，至少新增 24 条消息，并保留最近 16 条。AI 摘要只归纳旧聊天；网络失败时使用有界本地延续摘要，原文仍可检索，完整资料与每个历史推演从未截断。阈值以内不按每几个回合频繁压缩。摘要不能更改档案；后续关键问题仍直接附带所需资料和本轮结果。

## 7. 隐私与部署

只有 AI 调度/解读请求访问 DeepSeek；数值计算、资源加载、权限读取及保存均在本机。当前实现会把问题、必要资料及规则摘要发送 AI，因此 UI 明示这一点。内置城市表不进行地名网络查询。

本机开发凭据由已忽略的 Configuration/Secrets.local.json 管理，仓库只提交空白模板。Debug 构建读取该文件并在启动时同步变更到钥匙串；本地配置不存在时兼容读取上级 key 目录及 Finder textClipping。Release 构建不导入开发凭据，由使用者在设置中录入自己的 Key。提交钩子扫描完整暂存区，阻止私有配置及凭据值进入 Git。

## 8. 验收与已知边界

验收包括所有九插件的固定例、真实交节前后、未知时辰/时区/坐标、显式未知不得复用旧值、六爻概率与纳甲、流式 JSON/SSE、两个冲突选项、缓慢归一权重、资料不受压缩影响、两标签完整 UI 流程，以及独立可选的真实 API 计划→本地插件→流式解读链路。

首版能力边界：六爻/奇门仍是基础盘；姓名康熙表按精确字形查询，简繁转换候选须核对，现代笔画仅降级备用；紫微保留 iztro 本地 JavaScriptCore 内核；占星采用 Astronomy Engine 和等宫制；中国历法的全球历史地方时/交节并未逐地校准。所有这些在插件 descriptor、数据页和原始结果中可见，不由 AI 隐藏或升级成完整断法。
