# BlindOracle 架构与落地说明

## 1. 边界

本地插件负责数值、历法、抽牌、起卦和固定规则。AI 是可替换的语言服务，负责准备调用与交互计划、对话、资料澄清和中文解读整合，不能代算命盘或编造抽牌。位置、时区、城市和资料不确定性都作为输入，而非由模型暗中猜测。

本地「服务」采用同进程协议调用，不开启 HTTP 端口。iOS 的插件是随 App 签名发布的模块；新增原生算法通过应用更新交付，不下载执行未经签名的代码。

## 2. 插件契约

`OraclePlugin` 提供两项能力：

```swift
var descriptor: OraclePluginDescriptor { get }
func calculate(_ input: OracleInput) async throws -> OracleResult
```

descriptor 声明版本、必填/选填资料、适用问题、输出说明、边界、来源与许可，直接组成 AI 的工具目录。每个插件另有 Markdown 文档，位于 `Documentation/Plugins`。调用结果有 complete、partial、unavailable、failed 四种状态；每条规则证据包括语义倾向与强度，它们是规则元数据，不是现实概率。

注册表对计划进行方法白名单约束。`ReadingPreparationPolicy`结合 descriptor 与插件实际输入 guard，区分不能计算的硬缺项和允许partial输出的可选项；AI 无法通过计划删去本地要求。交互请求同样受本地方法与能力白名单约束，不能要求未选择的方法执行抽牌、报数或六爻起卦。当前每个插件暴露 `calculate` 一个入口，内部可按输入完整性返回局部能力。后续增加本命/流年等子接口时，可在 descriptor 扩充 operation 列表与相应参数类型。

扩展步骤：为 `OracleMethod` 增加稳定 ID；新增 conforming 插件和文档；加入 `NativePlugins.all` 或 `SkyPlugins.all`；需要用户操作时声明受支持的交互；增加可重复参考例、交互验证和未知资料测试；重新生成工程。结果与持久化统一使用 Codable 模型，文字结果沿用通用结果页。

## 3. 执行状态机

`idle → planning → awaitingIntake（统一表单） → awaitingInteraction（按需） → calculating → synthesizing → idle`。

问题先落盘。新推演通过`ChatView`自动展示`GroupIntakeView`统一资料表；已选人员的全部`ProfileFieldsView`在同一页展开，姓名、生辰、性别、地点、坐标、时区及必要报数一次核对。`ProfileFormDraft`按人员UUID独立保存编辑状态与墙上时间，单次最终确认才归一化为快照。日期、时刻用原生选择器，性别用菜单；`TimeZonePicker`提供系统完整时区列表及中文城市、地区、IANA检索，保存有效时区标识。出生地的定位快捷按钮仍须用户主动点击，不将设备时区冒充出生时区。

历史函数`prepareConversation`现在只准备完整表单，不逐字段发问，也不发送第二次确认汇总。旧计划恢复时清理`requestedProfileID`、`requestedFields`等逐项状态并重新打开统一表单。聊天保留“填写问事资料”入口；点击该入口或在聊天中回复确认只重新打开表单，不绕过最终提交。旧中文日期与时段解析器保留作为历史兼容，公历生日和独立姓/名仍不能由模型猜测。

`ReadingPreparationPolicy.evaluate`是纯Core策略，逐方法、逐人员输出blocking、optionalGaps、可执行方法与`OracleMethodOmission`。八字、称骨、占星必须有有效生日和已确认出生时区；未知时辰分别允许三柱/候选、骨重范围或全天星位区间。紫微需要生日、时辰、排盘性别和出生时区，姓名五格需要独立确认的姓氏和名字。表单集中展示必填缺项、可选限制和未采用方法，不为了可选能力强制用户反复补充未知资料。

用户明确指定的`mandatoryMethods`保留为硬约束：任一必要人员或字段不满足时，本次不能开算，也不换用其他方法代算。已明确未知的必要字段只说明其阻塞原因，不假装可以完成指定盘。混合方法按人员/方法对跳过不可用部分；`omittedMethods`记录缺失原因与对应人员，注册表不执行这些对，最终解读末尾须说明哪些方法未能提供参考。

`confirmGroupIntake`再次按全部提交人员执行准备策略，严格方法缺项时集中列出所有原因并保持表单打开；混合方法保留可执行方法、逐人缺项和说明。一次成功提交即生成输入，不再要求额外聊天确认。`intakeSessionID`拒绝已切换会话或已失效表单的保存和提交回调；重复提交在待填计划消耗后无效。`OraclePlan.draftParticipants/draftNumbers`只保存本轮未提交草稿，取消后可恢复，最终按用户选择另存永久档案。

确认后的`OracleInput`包含资料快照、起问时刻和随机种子。梅花要求报数时，在这张表内填写三个1至999的整数，提交后不再重复报数。抽牌翻牌与六爻投掷继续使用本地操作界面；资料表与必要操作共用一个Sheet，提交后直接切换，避免弹层重叠。未完成全部必要操作前不启动本地计算或AI汇总。实际交互写入输入快照后再调用插件，恢复交互和重新解读都使用已保存的输入，不重新随机。插件在后台异步逐项调用，逐项保存结果。

`OracleInteractionSession`保存本轮输入、计划、请求顺序、已完成响应及当前草稿。计划选择塔罗或六爻后，本地补齐相应交互，模型省略请求也不能绕过。每个响应须匹配当前步骤，数字、爻值、牌ID、牌位及翻牌数量由本地校验。过期会话ID的保存和完成回调被丢弃，避免写入另一段聊天。

塔罗是 `tarot` 独立方法。完整 78 张牌及正逆位牌义在本地提供；牌名和牌义保留英文，本次牌阵位置、实际牌面和朝向组成结构化结果，交给 DeepSeek 生成中文解读。模型不负责抽牌，牌面图片也不作为视觉输入发送。

每次任务有 operation UUID。停止会取消任务；旧网络增量和旧计算回调无法写入新对话。已完成的本地结果保留，可以重新请求 AI 解读。新对话保留档案和历史推演，也将原聊天收入历史侧栏；切换历史会话恢复其原文、摘要与待填问事笺，并取消之前的任务。新对话不会默认引用上一卷的结果。

`ReadingContinuationPolicy`在方法规划前判断当前聊天是否已有可用盘面：没有待补资料计划且已有complete/partial结果时，普通追问默认走延续解读，不创建问事单、交互或随机输入。只有明确重算、重新抽牌或换问题等请求才回到新推演准备。否定重算和询问重算含义不视为授权。`latestRun`按当前对话最后一条有效引用定位结果，不依全局记录创建顺序，也不在引用已删除后回退到旧问题。延续请求附带原问题、人员快照、已完成交互、全部可用结果、缺项与先前解读；原输入、牌面、爻值及保存的解读均保持不变。没有依据的细节如实解释限制，确需新推演时先请用户明确提出。

## 4. AI 与流式输出

使用 DeepSeek HTTPS chat/completions，默认模型为 DeepSeek Pro（`deepseek-v4-pro`），请求显式设置 `thinking.type=enabled`、`reasoning_effort=max`。每次调用提供 65,536 token 输出预算，包含推理与最终回答；请求超时 300 秒，资源总超时 900 秒。首次升级迁移旧版 Flash 默认值，迁移后用户主动选择的模型继续保留。

计划为 JSON，方法和资料字段被本地白名单解析；模型名通过设置可替换。汇总为流式 JSON，正文是首个 text 字段；增量 JSON 字符串解析器处理转义、分片和 Unicode，只把正文送到聊天 UI。接收 SSE 的 content，内部 reasoning_content 不解码、不展示、不保存。thinking 在服务端执行，客户端不将隐藏推理回传为后续对话。

处理进度由任务级步骤组成：准备调用计划、等待必要资料与汇总确认、各插件实际开始与结束、综合解读、输出整理。每步记录开始时间、状态与结束时间；插件步骤关联稳定方法ID。展开时保留这次任务的全部步骤，不按最近六项截断；默认折叠，仅显示当前步骤。进行中使用原生圆形`ProgressView`，置于标题过渡之外，标题和计时更新不会重建旋转指示器；等待用户时显示等待图标，完成、失败、取消均使用各自状态。开始下一步会结束上一步，失败和取消明确结束当前步骤，新任务重置这次进度。

这里展示应用实际执行的工作，不展示模型内部思维链。聊天记录使用独立裁剪的滚动区域，输入区位于其下方，以不透明背景覆盖底部安全区域；进度切换和展开收起时同步调整可见位置。

AI汇总仅接收complete/partial结果；partial限制必须保留，failed/unavailable不得作为证据。输入另外携带未使用方法及资料说明，要求在回答末尾自然交代其缺失原因，不能暗示被跳过的方法参与过判断。约四百字是提示词目标，用户追问可详细展开。解读请求失败时保留已确认的交互与本地结果，提供原结果重试入口；本地试算模式展示明确标识的规则摘要。

## 5. 分歧与偏好

提示词要求将轻微分歧合并，只在明显分歧时输出恰好两个处境选项。解析器验证选项 ID、实际支持者、白名单及两组互斥性；无效分组不展示为可学习选择。

初始权重按已注册的十种方法等分；升级时补入新增方法并保持归一化。每份推演只能产生一次偏好反馈；支持选择的权重乘 exp(0.035)，相反组乘 exp(-0.035)，未涉及者不作直接奖惩，再投影到归一化有界区间 4%–25%。一次反馈通常只改变不到一个百分点。此数值描述用户觉得更贴近的解释，不能称为方法准确率。已选择的分歧选项不会因重新解读而被悄悄替换。

## 6. 本地存储与上下文

### 具名多人档案

`OracleProfile`以稳定UUID区分人员，`name`为统一姓名；`resolvedName`按非空姓名、旧`familyName + givenName`、旧`displayName`兼容读取，排除“我、本人、他人资料”等占位值。档案不要求人物称谓，也不将数组首项默认绑定为本人。`OracleInput.participants`保存本次具名参与者的输入快照，`OraclePlan.participantIDs`只引用目录里已确认的UUID；多人的联合问事不混用各自生辰，也不因以后编辑永久档案而修改历史输入。

`Core/ProfileDirectory.swift`提供纯本地目录操作。`ProfileUpdate`的ID、统一姓名、独立`familyName/givenName`及各资料字段均为可选补丁；`applying(_:to:)`仅覆盖明确提供且格式有效的字段，其余原值保留。新记录必须有姓名；指定ID只能更新已有记录，未知ID不能直接新建。同名无明确ID时返回`ambiguousName`及候选UUID，不按顺序或最近使用时间选人。`resolve(names:in:)`也遵守同样的歧义规则，`referencedNames(in:profiles:)`使用完整姓名边界和长名优先规则，避免“李四海”命中“李四”。一次最多应用20条更新，姓名最多80字。显式改名使旧姓/名拆分失效，须重新确认；“名字：小明”在同一人员资料段中只补名字，不新建另一人。

出生日期与时刻另外保存规范`birthDateText`（YYYY-MM-DD）、`birthTimeText`（HH:mm或HH:mm:ss），支持先报时刻、后补生日，或以后再补出生时区。未提供时区时UTC只作内部存储锚点，并保留`unknownFields.birthTimeZone`；不向用户声明其出生地在UTC，也不从出生地推断时区。补充已知时区时按原墙上时间重建Date，保留用户原来的日历生日和时刻。`unknownFields`表示当前不可用字段，`declaredUnknownFields`另外记录用户明确说不确定的字段：新档案缺资料不会因此被误认为已经问过；旧记录缺少该字段时兼容沿用原未知标记。明确未知优先于同条冲突值，有效补充清除对应两组标记。未知时刻不变成已知中午，内部中午仅作日期存储占位，不参与时柱。

`parseExplicitUpdates(in:profiles:)`为明确具名补充提供本地语法，支持逗号、分号、换行分隔的多人生日、性别，以及既有姓名后补出生时刻、地点、时区、姓氏和名字。当前待答字段由`ConversationalIntake`单独绑定，避免将短答复扫入其他人的资料。无字段范围的普通“他、她、我”不用于猜测人物。`explicitSelfName(in:profiles:)`仅接受姓名后有标点或句末的“我叫/我是”直接声明，“我是张三的朋友”不会绑定为张三。

AI只提交`ProfileUpdate`候选，不直接写档案。`groundedUpdates(_:in:profiles:contextIDs:)`按本条消息、同一具名人员的明确资料逐字段佐证，剥离默认值、其他人的事实与未提供的未知标记。仅有一个已明确选择的context ID且本条没有其他具名人员时，才允许绑定省略姓名的补充；多人上下文不代猜。同名情况下，模型自行选择一个UUID不能绕过本地歧义确认。

Application Support/BlindOracle：profiles.json（永久资料）、readings.json（每次快照与逐项结果）、preferences.json（全局个人偏好）、conversation-history.json（版本化会话列表与当前ID）。每段聊天拥有自己的消息、摘要、待填资料计划与待完成交互；计划保存原问题、指定方法、参与者、表单草稿、核对快照及未使用方法说明。切换或重启后继续当前对话准备阶段。conversation.json、context.json、pending-intake.json继续作为兼容快照保存；旧待填计划迁移为统一资料表，不再逐字段询问。新增字段兼容旧JSON缺失字段，旧推演仍按原输入读取，不为历史记录补抽牌。

资料库的留存人员以完整列表平铺，不按前几项截断；每行直接编辑或删除。删除永久档案不修改已保存推演的参与者快照。

推演记录的最近与全部列表共用独立的导航区域、右侧删除按钮和确认对话框。`OracleStore.deleteReading(id:)`按UUID移除本次记录并写回磁盘，清理当前及归档聊天的`runID`，以可选`deletedRunID`保留已删除引用的状态；聊天正文、人员资料和偏好不联动删除。最新引用已删除时不回退到另一道问题的盘面；陈旧的重试对象也不能重新触发解读。删除当前计算或解读的记录会取消对应任务并作废操作标识，其他记录的进行中任务保持独立。

任务步骤以可选 `OracleRun.activities` 随推演保存，包含各插件实际执行及后续解读的状态和耗时；旧记录没有该字段时仍可读取。步骤文本是应用工作记录，不包含模型隐藏推理。

首次升级会迁移旧 conversation-<timestamp>.json 归档，按消息 UUID 去重。版本化历史文件一旦存在即为权威来源，即使删光聊天也不会重新导入旧档案。长按删除只移除该聊天，不联动删除独立推演、基础档案或个人偏好。聊天内「翻看数据」以消息的 runID 打开专属结果 Sheet，展示该次每个方法原始返回，不跳转全局数据总览。

JSON 原子写入并启用首次解锁后文件保护；目录排除自动云备份。应用运行时将凭据保存于 ThisDeviceOnly 钥匙串，不进入资料 JSON、对话、日志或导出。用户主动导出的备份包含个人资料与推演，不包含密钥。

压缩阈值约 32k 估算 token，至少新增 24 条消息，并保留最近 16 条。AI 摘要只归纳旧聊天；网络失败时使用有界本地延续摘要，原文仍可检索，完整资料与每个历史推演从未截断。阈值以内不按每几个回合频繁压缩。摘要不能更改档案；后续关键问题仍直接附带所需资料和本轮结果。

## 7. 隐私与部署

AI 调度/解读请求访问 DeepSeek；数值计算、资源加载、权限读取及保存均在本机。当前实现会把问题、必要资料及规则摘要发送 AI，因此 UI 明示这一点。内置城市表不进行地名网络查询。用户主动点击出生地或当前所在地的定位按钮后，系统取得坐标并通过 Apple 地理服务查询地点与当地时区；iOS 26及以上使用MapKit逆地理编码，旧系统使用可用性限定的CoreLocation接口。两处定位各用独立请求状态，取消/过期回调不写回；失败保留原资料，不以设备时区猜测地点时区。

本机开发凭据由已忽略的 Configuration/Secrets.local.json 管理，仓库只提交空白模板。Debug 构建读取该文件并在启动时同步变更到钥匙串；本地配置不存在时兼容读取上级 key 目录及 Finder textClipping。Release 构建不导入开发凭据，由使用者在设置中录入自己的 Key。提交钩子扫描完整暂存区，阻止私有配置及凭据值进入 Git。

## 8. 验收与已知边界

验收用例覆盖所有十插件的固定例、真实交节前后、未知时辰/时区/坐标、显式未知不得复用旧值、严格方法缺项阻塞、混合方法逐人跳过及原因说明、当前待答人员/字段绑定、时段与公历确认、汇总快照确认及更改后重新确认、独立姓/名补充、六爻概率与纳甲、塔罗完整牌库与无重复抽牌、聊天报数与物理交互校验、交互保存恢复和旧JSON兼容、重试不重抽、流式JSON/SSE、两个冲突选项、缓慢归一权重、资料不受压缩影响、完整人员列表与两标签UI流程，以及独立可选的真实API计划→用户确认与交互→本地插件→流式中文解读链路。

首版能力边界：六爻/奇门仍是基础盘；姓名康熙表按精确字形查询，简繁转换候选须核对，现代笔画仅降级备用；紫微保留 iztro 本地 JavaScriptCore 内核；占星采用 Astronomy Engine 和等宫制；中国历法的全球历史地方时/交节并未逐地校准。所有这些在插件 descriptor、数据页和原始结果中可见，不由 AI 隐藏或升级成完整断法。
