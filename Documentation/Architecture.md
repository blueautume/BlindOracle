# BlindOracle 架构与落地说明

## 1. 边界

本地插件负责数值、历法、抽牌、起卦和固定规则。AI 是可替换的语言服务，负责准备调用与交互计划、对话、资料澄清和中英文解读整合，不能代算命盘或编造抽牌。位置、时区、城市和资料不确定性都作为输入，而非由模型暗中猜测。

本地「服务」采用同进程协议调用，不开启 HTTP 端口。iOS 的插件是随 App 签名发布的模块；新增原生算法通过应用更新交付，不下载执行未经签名的代码。

## 2. 插件契约

`OraclePlugin` 提供两项能力：

```swift
var descriptor: OraclePluginDescriptor { get }
func calculate(_ input: OracleInput) async throws -> OracleResult
```

descriptor 声明版本、必填/选填资料、适用问题、输出说明、边界、来源与许可，直接组成 AI 的工具目录。每个插件另有 Markdown 文档，位于 `Documentation/Plugins`。调用结果有 complete、partial、unavailable、failed 四种状态；每条规则证据包括语义倾向与强度，它们是规则元数据，不是现实概率。

注册表对计划进行方法白名单约束。`ReadingPreparationPolicy`结合 descriptor 与插件实际输入 guard，区分不能计算的硬缺项和允许partial输出的可选项；AI 无法通过计划删去本地要求。交互请求同样受本地方法与能力白名单约束，不能要求未选择的方法执行抽牌、报数或六爻起卦。当前每个插件暴露 `calculate` 一个入口，内部可按输入完整性返回局部能力。后续增加本命/流年等子接口时，可在 descriptor 扩充 operation 列表与相应参数类型。

扩展步骤：为 `OracleMethod` 增加稳定 ID；新增 conforming 插件和文档；加入 `NativePlugins.all` 或 `SkyPlugins.all`；需要用户操作时声明受支持的交互；增加可重复参考例、交互验证和未知资料测试；重新生成工程。结果与持久化统一使用 Codable 模型，文字结果沿用通用结果页。

## 3. 执行状态机

新推演主流程为`idle → planning → awaitingIntake（统一表单） → awaitingInteraction（按需） → calculating → synthesizing → idle`。已有问事按`reply / supplement / intake`分流：普通解释直接解读已有结果；补算按真实缺项进入表单或必要交互，输入已知有效时可直接计算新增或变化部分；新问题与明确重新起卦仍走完整的新推演流程。

问题先落盘。新推演通过 `ChatView` 自动展示 `GroupIntakeView` 统一资料表。每位参与人的姓、名、代称、性别、出生日期、出生时刻、出生地和当前所在地平铺在同一页，并按方法显示必要报数。`ProfileFormDraft` 按人员 UUID 独立保存编辑状态和当地钟表时间。问事草稿在短暂编辑停顿后保存，在离开表单或切入后台时立即保存；最终确认时才归一化为推演输入快照。出生日期、时刻独立选择和清空。出生地使用本地地区目录按省、市、区县选择，自动设置时区。当前所在地由用户主动发起定位。其下方新增只读八字行，直接调用共享 TrueSolarBaziEngine 显示原始中文四柱，并按出生输入键取消和淘汰过期预览；正式八字插件委托同一内核。

历史函数`prepareConversation`现在只准备完整表单，不逐字段发问，也不发送第二次确认汇总。旧计划恢复时清理`requestedProfileID`、`requestedFields`等逐项状态并重新打开统一表单。聊天保留“填写问事资料”入口；点击该入口或在聊天中回复确认只重新打开表单，不绕过最终提交。旧中文日期与时段解析器保留作为历史兼容，公历生日和独立姓/名仍不能由模型猜测。

人员解析在客户端再次以当前问题中的完整姓名为准，模型返回空ID数组不阻断明确本人绑定或唯一姓名匹配。`defaultParticipants`保持明确选择语义；统一表单可将唯一已存档案预填为候选，但不设置selfProfileID，也不跳过用户确认。同名、多人或明确他人问题不随意默认选人。`ProfileDirectory.restoringKnownFields`按同一UUID回补陈旧草稿中未声明未知的缺失字段，保留主动修改和明确未知，并复用墙上时间归一化避免补时区后改变钟表时刻。AI目录补充时区、出生地点的已知状态与明确未知标记，不为路由额外发送未选人员的地点值；若计划仍在聊天索要姓名、生辰或时区，已有具体问事会被本地路由回统一表单。

`ReadingPreparationPolicy.evaluate`是纯Core策略，逐方法、逐人员输出blocking、optionalGaps、可执行方法与`OracleMethodOmission`。八字、称骨、占星必须有有效生日和已确认出生时区；八字还必须有可用出生坐标以校正真太阳时。未知时辰分别允许年/月/日柱候选、骨重范围或全天星位区间。紫微需要生日、时辰、排盘性别和出生时区，姓名五格需要独立确认的姓氏和名字。表单集中展示必填缺项、可选限制和未采用方法，不为了可选能力强制用户反复补充未知资料。

用户明确指定的 `mandatoryMethods` 在普通提交时是硬约束，任一必要人员或字段不满足就保留表单。混合方法按人员和方法跳过不可用部分。没有必选方法、所有候选均不可执行且小六壬已加载时，准备策略返回小六壬作为问事参考。`omittedMethods` 仍记录原候选方法缺失的资料和对应人员，最终解读说明哪些方法未能提供参考。

`confirmGroupIntake` 再次按全部提交人员执行准备策略。必选个人方法缺资料时，用户可以用单独的“改用小六壬”操作选择问事参考。一次成功提交即生成输入并继续流程。`intakeSessionID` 拒绝已切换会话或已失效表单的保存和提交回调，待填计划消耗后重复提交无效。`OraclePlan.draftParticipants/draftNumbers` 保存本轮未提交草稿，取消后可恢复，最终按用户选择另存永久档案。

确认后的`OracleInput`包含资料快照、起问时刻和随机种子。梅花要求报数时，在这张表内填写三个1至999的整数，提交后不再重复报数。抽牌翻牌与六爻投掷继续使用本地操作界面；资料表与必要操作共用一个Sheet，提交后直接切换，避免弹层重叠。未完成全部必要操作前不启动本地计算或AI汇总。实际交互写入输入快照后再调用插件，恢复交互和重新解读都使用已保存的输入，不重新随机。插件在后台异步逐项调用，逐项保存结果。

`OracleInteractionSession`保存本轮输入、计划、请求顺序、已完成响应及当前草稿。计划选择塔罗或六爻且尚无有效保存选择时，本地补齐相应交互，模型省略请求也不能绕过。同一问事补算保留已有牌面、爻值、报数及交互响应，仅为新增方法缺少的操作建立新步骤；完成新步骤时合并响应，不覆盖其他方法的已完成交互。每个响应须匹配当前步骤，数字、爻值、牌ID、牌位及翻牌数量由本地校验。过期会话ID的保存和完成回调被丢弃，避免写入另一段聊天。

塔罗是 `tarot` 独立方法。完整 78 张牌及正逆位牌义在本地提供；牌名和牌义保留英文，本次牌阵位置、实际牌面和朝向组成结构化结果，交给选定的 AI 服务生成所需语言的解读。模型不负责抽牌，牌面图片也不作为视觉输入发送。

每次任务有 operation UUID。停止会取消任务；旧网络增量和旧计算回调无法写入新对话。已完成的本地结果保留，可以重新请求 AI 解读。新对话保留档案和历史推演，也将原聊天收入历史侧栏；切换历史会话恢复其原文、摘要与待填问事笺，并取消之前的任务。新对话不会默认引用上一卷的结果。

`latestRun`按当前对话最后一条有效引用定位已有问事，不依全局记录创建顺序，也不在引用已删除后回退到旧问题。规划接收原问题、完整输入、方法与人员归属、可用结果及先前解读：已有依据足够的解释或展开走`reply`；本条需求确需尚未覆盖的能力，或相关资料、人员、条件变化时走`supplement`；明确重新起卦、重新抽牌或真正不同的新问题走`intake`。单纯提到方法、要求详细解释、否定重算或询问重算含义，不构成重新计算要求。

局部补算的输入变化须能定位到出生资料、人员、坐标、时区等实际字段；事件目标、所问时段或关键约束已实质改变、原起卦所问不再成立时，规划为新问事并重新确认。普通背景补充、情绪变化或时间自然流逝本身不构成重新起卦条件。

`ReadingContinuationPolicy.reusableResults`按方法和人员UUID比较实际参与计算的输入，Store再核对插件版本。相同方法、相同人员、相关输入未变化的complete/partial结果直接复用；不同人员分别判断，failed/unavailable不作为已完成结果。姓名、出生资料、起问时区、报数、牌面与爻值等只影响实际依赖它们的方法，无关档案编辑、消息增加或时间自然流逝不会触发全部重算。注册表跳过复用项，仅对新增或失效的方法/人员对执行插件，进度数量也只统计实际执行项。partial的限制继续保留，不以相同输入重复计算来假装补齐能力。

同一问事补算沿用原起问时刻、随机种子及已确认交互。缺少必要资料时打开统一表单，已知有效输入可直接进入补算；新增塔罗或六爻且缺少保存的选择时才请求对应操作。补算建立新的`OracleRun`，将仍有效的结果完整复制到新记录，再合并新计算结果统一解读。`OraclePlan.baseRunID`、`followUpQuestion`与`OracleRun.reusedResultIDs`记录来源和本条补充诉求，原盘的输入、牌面、爻值和解读不被修改。删除源记录会取消依赖它的待填或待交互补算；已经完成的补算保存独立快照与结果，可继续查看和解读。无法由现有或新增能力支持的细节如实说明限制，不编造依据。

## 4. AI 与流式输出

设置中的服务选择保存在 `oracle.aiProvider`，初始使用 DeepSeek Pro（`deepseek-v4-pro`）。DeepSeek 请求使用 `thinking.type=enabled` 和 `reasoning_effort=max`。千问通过百炼北京的 OpenAI 兼容端点调用 `qwen3.8-max-0902`，使用 `enable_thinking=true` 和 `reasoning_effort=xhigh`。两种服务均提供 65,536 token 的推理及回答预算，请求超时为 300 秒，资源总超时为 900 秒。旧版 DeepSeek Flash 默认值会在首次升级时迁移，用户之后主动设置的 DeepSeek 模型继续保留。

设置中的连接检查由用户主动发起，展示当前设备的请求模型、API 返回模型以及 thinking、推理强度和输出预算参数。真机排查依据该设备的配置与检查结果；未连接、未取得设备配置时，不用本机或模拟器的状态代替手机诊断。

计划为 JSON，方法和资料字段被本地白名单解析；模型名通过设置可替换。汇总为流式 JSON，正文是首个 text 字段；增量 JSON 字符串解析器处理转义、分片和 Unicode，只把正文送到聊天 UI。接收 SSE 的 content，内部 reasoning_content 不解码、不展示、不保存。thinking 在服务端执行，客户端不将隐藏推理回传为后续对话。

处理进度由任务级步骤组成：准备调用计划、等待必要资料与汇总确认、各插件实际开始与结束、综合解读、输出整理。每步记录开始时间、状态与结束时间；插件步骤关联稳定方法ID。展开时保留这次任务的全部步骤，不按最近六项截断；默认折叠，仅显示当前步骤。进行中使用原生圆形`ProgressView`，置于标题过渡之外，标题和计时更新不会重建旋转指示器；等待用户时显示等待图标，完成、失败、取消均使用各自状态。开始下一步会结束上一步，失败和取消明确结束当前步骤，新任务重置这次进度。

这里展示应用实际执行的工作，不展示模型内部思维链。聊天记录使用独立裁剪的滚动区域，输入区位于其下方，以不透明背景覆盖底部安全区域；进度切换和展开收起时同步调整可见位置。

AI汇总仅接收complete/partial结果；partial限制必须保留，failed/unavailable不得作为证据。输入另外携带未使用方法及资料说明，要求在回答末尾自然交代其缺失原因，不能暗示被跳过的方法参与过判断。首次解读与追问共用直接表达要求：首句回答问题，明确有依据的倾向，再用具体结果解释原因；禁止用“各有利弊、顺其自然”等套话代替判断。无法判断的部分直接交代缺失依据，不编造确定性。主要解读通常为 250–400 个汉字或 150–250 个英文单词；简单问题短答，详细追问按需展开。解读请求失败时保留已确认的交互与本地结果，提供原结果重试入口；本地试算模式展示明确标识的规则摘要。

### 中英双语

`AppLanguage` 跟随 iOS 为本应用选择的语言，或读取「设置」中的中英文覆盖。SwiftUI 环境接收相应区域格式，界面文案走字符串目录或 `L10n.text`。地区 ID、原始地点、历法输入、档案和已保存的交互独立于语言；英文界面用英文或拼音显示原有地区目录。

每次 AI 规划、解读、追问及摘要请求显式传入语言，用户明确指定的回复语言优先。方法、字段、牌位、动作、档案 ID 和现有 JSON 值保持稳定。英文聊天中的重抽、补算与人员资料也经过同一套本地校验。推演结果记录生成语言；旧结果和旧聊天按原文显示，继续追问时使用当前回复语言。易经卦辞和称骨诗的英文释义随包提供，并保留中文原文。

## 5. 分歧说明

解读存在真实分歧时直接在正文说明各自依据、成立条件和可观察的区别，不限定为两组，也不要求用户挑选解释。轻微差异自然整合，不能人为制造冲突。没有方法偏好权重、选择反馈、学习更新、权重快照或重置机制；新请求不传这类数据。

旧推演中的选项标题和说明只兼容为 `ReadingSynthesis.archivedConflictDetails` 静态文字，聊天保留原回复并附上旧分歧说明，不再提供可选按钮。旧 JSON 中的选择与权重字段被忽略，新编码不再写出。旧 `choice` 消息保留在历史记录中，但出站对话和本地/联网摘要都排除这些消息；摘要规则也明确不从旧摘要恢复偏好反馈。启动只清理退役的 `preferences.json` 及其专属恢复副本，保留档案、推演、聊天和语言/口吻设置。

## 6. 本地存储与上下文

### 匿名与具名多人档案

`OracleProfile` 以稳定 UUID 区分人员。`resolvedName` 继续兼容统一姓名、`familyName + givenName` 与旧 `displayName`，排除“我、本人、他人资料”等占位值。`participantLabel` 依次使用别名、可用姓名和从 UUID 派生的四位代号。四位代号可能重复，实际选人与结果归属使用 UUID。`isAnonymousRecord` 用于区分主动保存的空白档案和旧版空占位记录。`OracleInput.participants` 保存本次参与者的输入快照，后续编辑永久档案不会修改历史输入。

`Core/ProfileDirectory.swift` 提供本地目录操作。`ProfileUpdate` 只修改明确提供且格式有效的字段，或将明确清空的字段标为未知。用户可在表单中直接创建匿名档案，聊天补丁只有具名内容才能创建新档案。指定 UUID 的补丁可更新已有匿名档案，未知 UUID 不会新建记录。姓名有歧义时返回候选 UUID，交由用户选取。姓名匹配使用完整边界和长名优先规则，避免“李四海”命中“李四”。一次最多应用 20 条补丁，姓名最多 80 字。显式改名后需要重新确认姓和名的拆分。

出生日期和时刻分别保存在 `birthDateText` 和 `birthTimeText`，允许先填其中一项。新资料默认使用 `Asia/Shanghai`。旧资料的未确定或无效出生时区在保存或生成新推演输入时应用该默认值，按旧时区或文本保存的当地日期和时刻重建 `Date`。已确认的有效时区和历史推演快照保留原值。`unknownFields` 表示当前不可用，`declaredUnknownFields` 另外记录明确未知或清空的字段，防止同 UUID 的旧档案补回这些值。出生地坐标只从同一地区或整组未填写的旧资料回补。缺失时刻时，内部中午仅作日期存储占位，不参与时柱。

`parseExplicitUpdates(in:profiles:)`为明确具名补充提供本地语法，支持逗号、分号、换行分隔的多人生日、性别，以及既有姓名后补出生时刻、地点、时区、姓氏和名字。当前待答字段由`ConversationalIntake`单独绑定，避免将短答复扫入其他人的资料。无字段范围的普通“他、她、我”不用于猜测人物。`explicitSelfName(in:profiles:)`仅接受姓名后有标点或句末的“我叫/我是”直接声明，“我是张三的朋友”不会绑定为张三。

AI只提交`ProfileUpdate`候选，不直接写档案。`groundedUpdates(_:in:profiles:contextIDs:)`按本条消息、同一具名人员的明确资料逐字段佐证，剥离默认值、其他人的事实与未提供的未知标记。仅有一个已明确选择的context ID且本条没有其他具名人员时，才允许绑定省略姓名的补充；多人上下文不代猜。同名情况下，模型自行选择一个UUID不能绕过本地歧义确认。

Application Support/BlindOracle：profiles.json（永久资料）、readings.json（每次快照与逐项结果）、conversation-history.json（版本化会话列表与当前ID）。每段聊天拥有自己的消息、摘要、待填资料计划与待完成交互；计划保存原问题、指定方法、参与者、表单草稿、核对快照及未使用方法说明。切换或重启后继续当前对话准备阶段。conversation.json、context.json、pending-intake.json继续作为兼容快照保存；旧待填计划迁移为统一资料表，不再逐字段询问。新增字段兼容旧JSON缺失字段，旧推演仍按原输入读取，不为历史记录补抽牌。

资料库的留存人员以完整列表平铺，不按前几项截断；每行直接编辑或删除。删除永久档案不修改已保存推演的参与者快照。

`OracleStore.deleteReading(id:)`按UUID移除本次记录并写回磁盘，清理当前及归档聊天的`runID`，以可选`deletedRunID`保留已删除引用的状态；聊天正文与人员资料不联动删除。最新引用已删除时不回退到另一道问题的盘面；陈旧的重试对象也不能重新触发解读。删除当前计算或解读的记录会取消对应任务并作废操作标识，其他记录的进行中任务保持独立。

任务步骤以可选 `OracleRun.activities` 随推演保存，包含各插件实际执行及后续解读的状态和耗时；旧记录没有该字段时仍可读取。步骤文本是应用工作记录，不包含模型隐藏推理。

首次升级会迁移旧 conversation-<timestamp>.json 归档，按消息 UUID 去重。版本化历史文件一旦存在即为权威来源，即使删光聊天也不会重新导入旧档案。长按删除只移除该聊天，不联动删除独立推演或基础档案。聊天内「翻看数据」以消息的 runID 打开专属结果 Sheet，展示该次每个方法的原始返回。

JSON 原子写入并启用首次解锁后文件保护；目录排除自动云备份。应用运行时将凭据保存于 ThisDeviceOnly 钥匙串，不进入资料 JSON、对话或日志。设置中的本机资料/备份入口已移除，档案和历史持久化保持独立。

压缩阈值约 32k 估算 token，至少新增 24 条消息，并保留最近 16 条。AI 摘要只归纳旧聊天；网络失败时使用有界本地延续摘要，原文仍可检索，完整资料与每个历史推演从未截断。阈值以内不按每几个回合频繁压缩。摘要不能更改档案；后续关键问题仍直接附带所需资料和本轮结果。

## 7. 隐私与部署

AI 调度和解读请求发往设置中所选的服务，UI 明示会发送问题、必要资料和规则摘要。数值计算、内置地区目录和资料保存均在本机。选择出生地区无需定位权限。离线目录缺少坐标时，所选服务只接收区划名称和代码以生成查询，Apple 地理服务核对区划后才回填坐标，失败仍保留所选地区。用户主动点按定位时，可用设备坐标填写出生地或当前所在地，经 Apple 地理服务确认在支持范围内，新资料使用北京时间。iOS 26 及以上使用 MapKit 地理编码，旧系统使用 Core Location 接口。地区查询与定位分别处理过期和取消回调。

Debug 与 Release 可分别生成包内 DeepSeek 密钥 `dev-key.txt` 与千问密钥 `qwen-key.txt`。配置来源和优先级见[配置说明](../Configuration/README.md)。两种凭据独立保存在钥匙串，当前服务的内置凭据在启动或切换后导入。安装包内置密钥可被提取，本次仅面向已授权分发。

启动导入使用`AfterFirstUnlockThisDeviceOnly`钥匙串，设置中手工保存的凭据与来源不明的已有凭据优先保留。只有现存凭据的SHA-256指纹匹配上次成功导入的bundle key，且未标记为手工保存时，才随新包自动轮换；指纹在钥匙串写入成功后更新，`UserDefaults`只存指纹和来源标记。空配置不带密钥资源，也不删除设备中的用户凭据。提交钩子继续扫描完整暂存区，阻止私有配置及凭据值进入Git。

## 8. 验收与已知边界

验收用例覆盖所有十插件的固定例、真实交节前后、未知时辰/时区/坐标、显式未知不得复用旧值、严格方法缺项阻塞、混合方法逐人跳过及原因说明、当前待答人员/字段绑定、时段与公历确认、汇总快照确认及更改后重新确认、独立姓/名补充、六爻概率与纳甲、塔罗完整牌库与无重复抽牌、聊天报数与物理交互校验、交互保存恢复和旧JSON兼容、重试不重抽、流式JSON/SSE、两个冲突选项、缓慢归一权重、资料不受压缩影响、完整人员列表与两标签UI流程，以及独立可选的真实API计划→用户确认与交互→本地插件→流式中文解读链路。

首版能力边界：六爻/奇门仍是基础盘；姓名康熙表按精确字形查询，简繁转换候选须核对，现代笔画仅降级备用；紫微保留 iztro 本地 JavaScriptCore 内核；占星采用 Astronomy Engine 和等宫制；中国历法的全球历史地方时/交节并未逐地校准。所有这些在插件 descriptor、数据页和原始结果中可见，不由 AI 隐藏或升级成完整断法。

## 9. 稳定性实施计划（2026-11-03）

本轮先围绕“输入确认 → 异步计算 → 流式解读 → 保存 → 重启恢复”加固故障边界。维持现有插件、档案 UUID 和文件格式，先用回归测试固定行为，再逐步拆分状态机与存储职责。

| 优先级 | 范围 | 实施与验收 |
|---|---|---|
| P0，本轮实现 | 流式正文 | 按 Unicode 标量增量解析顶层 `text`，跨分片组合音标、emoji、代理对与 JSON 转义完整输出；嵌套元数据不进入正文。 |
| P0，本轮实现 | 历史恢复 | 一条会话损坏时恢复其他有效会话；覆盖前保留原文件；备份失败时拒绝覆盖。空历史与未知 schema 仍不重新导入旧归档。 |
| P0，本轮实现 | 生命周期 | 解读开始前保存任务状态，进入后台保存当前部分正文；重启时把已中断步骤标为取消并持久化，保留本地结果，空回复显示中断说明。后台保存不取消仍在运行的任务。 |
| P0，本轮实现 | 定位隔离 | 每次请求独立 manager，校验所有定位与授权回调的实例身份；取消再重试后，上次回调不能结束或污染新请求。 |
| P1，后续 | 存储一致性与规模 | 多个 JSON 文件当前分别原子写入，尚无跨文件事务。增加故障注入验证，再设计整批快照的提交与恢复机制；大历史转为按会话增量保存，减少主线程全量编码。 |
| P1，后续 | 状态机拆分 | 将 OracleStore 的任务调度、会话持久化和表单状态逐步拆成独立职责，保留 operation/session UUID 校验；每次只迁移一条已覆盖流程。 |
| P2，后续 | 持续验证 | 自动化运行单元测试、关键 UI 流程和 Release 构建，保留版本对应的 xcresult；补充最低支持系统、真机后台终止及磁盘空间不足验证。 |

当前后台检查点保存的是进入后台当时已接收的正文；之后才收到、但尚未完成保存的分片，进程被系统终止时仍可能丢失。不会自动重发网络解读或重新抽牌，以免把恢复动作变成新一轮推演。真实 API 和真机验证与离线回归分开记录，具体本轮证据见 `Validation.json`，历史证据继续保留实际所属版本。

## 真太阳时八字（3.0.12）

本地 `TrueSolarBaziEngine` 使用出生地经度和 NOAA Julian-century 均时差校正日/时柱，年/月柱按真实瞬间对照固定 UTC+08:00 交节，起运间隔也使用真实时刻。未知时刻检查出生民用日期全天候选；地点未确认或明确撤回时不回退钟表盘、不借用当前所在地。准备策略将出生坐标作为八字硬要求；追问复用策略比较有效出生坐标及撤回状态，地点变化后重算，历史快照不被改写。预览与固定规则完全离线，最终自然语言问事解读仍沿用现有在线服务。

## 数据页首次切换（3.0.14）

留存资料摘要经 `profileSummary` 读取 `ChinaDistrictCatalog.shared`。旧实现首次构造目录时同步生成所有中文/英文地点匹配键，导致中文界面仅显示地名也要支付全量英文转写成本。该构造发生在数据页首次显示的主线程调用中；文件读取与 JSON 解码只占小部分，主要成本是完整地名索引的字符串规范化和英文/拼音转写。

目录构造现在仅建立层级和显示索引。完整中文路径索引、英文别名索引分别按需创建，使用 `NSLock` 保护首次并发访问，并保留完整父级路径及同名拒绝规则。ASCII 匹配键直接规范化，不经过繁简与 Unicode 转换。显示、浏览地区不触发匹配索引。

Apple M2 上独立 Foundation 提取代码、三个新进程 Release 基准的中位数：目录初始化约 793.4 ms → 14.8 ms；首次英文匹配索引约 779.1 ms → 204.1 ms；千次热英文匹配约 15.4 ms → 1.0 ms。这些是代码段基准，不代表真机整页切换帧时间。确定性回归覆盖显示不构建索引、中文匹配不构建英文索引、并发首次匹配及原有英文别名/同名区县行为。
