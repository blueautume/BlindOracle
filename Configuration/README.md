# 内置解读服务配置

应用统一使用内置 DeepSeek Pro，固定启用深度思考和 max 推理强度。用户界面不提供供应商、模型、凭据或离线解读设置；规划、综合解读和追问均需联网，网络或服务失败时保留资料与已完成盘面供重试。

开发配置优先读取被 Git 忽略的 `Secrets.local.json` 中的 `deepseek_api_key`。该文件缺失时，兼容工程上一级 `key` 目录的原有 Finder 文本剪辑。`Secrets.example.json` 只提供空白模板；不要把真实凭据提交到仓库。

Debug 与 Release 使用同一配置，生成唯一的包内资源 `dev-key.txt`。修改开发配置后重新构建即可更新资源。脚本以 `0600` 权限原子写入；配置无效时清理旧资源并使构建失败。将字段设为空字符串会移除随包凭据，应用仍要求联网解读并显示可重试的服务错误。每次构建会删除旧的千问资源，不再读取或打包其配置。

应用沿用 `com.blindoracle.deepseek` 服务下 `api-key` 的 `AfterFirstUnlockThisDeviceOnly` 钥匙串条目。没有有效凭据时导入内置资源；早期版本手工保存或来源不明的已有条目保持不变。只有当前条目仍匹配上次成功导入的 SHA-256 指纹且未标记为手工保存时，才随新包轮换。`UserDefaults` 只保存指纹与来源标记，不保存凭据。

凭据不进入源码、Git、用户导出备份或日志；生成资源和构建目录保持忽略。安装包中的内置凭据可被提取，分发范围见[项目 README](../README.md)。连接模型和请求报告只用于内部验证，不向用户呈现。
