# 本地与随包密钥

复制 `Secrets.example.json` 为 `Secrets.local.json`，在 `deepseek_api_key` 填写自己的 DeepSeek 密钥。

`Secrets.local.json` 已加入 `.gitignore`，不要强制加入版本控制。仓库中的模板不含任何有效凭据。

按本次用户明确要求，Debug 与 Release 都从同一份本地忽略配置生成包内 `dev-key.txt`，供授权分发的安装包直接使用。修改配置后重新构建即可更换包内密钥；资源原子生成，写入权限为 `0600`，不把值打印到构建日志。配置无效时构建失败并移除陈旧资源；配置中的密钥为空时移除资源，不将上次构建的密钥带入新包。

应用启动时将随包密钥导入 `AfterFirstUnlockThisDeviceOnly` 钥匙串。没有有效凭据时导入；用户在设置中手工保存的密钥，以及来源不明的已有密钥，均保留。只有当前钥匙串凭据仍匹配上次成功导入的 bundle key 指纹，且未被标记为手工保存时，才随新包密钥轮换；写入成功后更新 SHA-256 指纹。`UserDefaults` 只保存指纹与来源标记，不保存密钥值。空配置不向包内写密钥，也不会删除已安装设备中的手工凭据。

为兼容旧工程，本地配置文件不存在时，构建脚本仍可读取工程上一级 `key` 文件夹。存在但为空的本地配置不会回退到旧密钥。

密钥值不进入程序源码、Git、用户导出备份或日志；生成资源和构建目录仍被忽略。安装包内置密钥可被提取，分发范围与说明见[项目 README](../README.md)。

「数据 → 设置」的连接检查可核对当前设备发送的模型、API 返回模型，以及 `thinking`、`reasoning_effort=max` 和输出预算参数。排查真机时应读取该设备的设置和检查结果，不能用开发机或模拟器的状态代替。
