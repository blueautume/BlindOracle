# 瞎子 · BlindOracle

一个以水墨宣纸为视觉语言的原生 SwiftUI iOS 应用。只有「对话」「数据」两个标签。十种方法在设备本地执行，DeepSeek 负责选择适用插件、提出资料与交互需求、整合中文解读和回答追问。

当前版本：**0.1.5（Build 6）**。

每批修改提交前同时递增补丁版本和 Build，运行一次 `python3 Scripts/version.py` 即可同步版本配置。单一版本源为 `Configuration/Version.json`，工程生成脚本也从这里读取；构建和测试不会自动加版本。`python3 Scripts/version.py --check` 检查工作区同步状态，提交钩子用 `--check-staged` 检查暂存区相对 HEAD 的递增。首次克隆后使用 `git config core.hooksPath .githooks` 启用密钥及版本检查。

## 打开与运行

1. 用 Xcode 27.1 打开 `BlindOracle.xcodeproj`，选择 `BlindOracle` scheme。
2. 选择 iOS 17 或更高版本的模拟器运行。真机需在 Signing & Capabilities 选择自己的开发团队；本项目的 bundle identifier 保持为 `com.lihao.BlindOracle`。
3. 将 `Configuration/Secrets.example.json` 复制为 `Configuration/Secrets.local.json`，填写 `deepseek_api_key`。本地密钥文件已被 Git 忽略，仓库只保留空白模板。Debug 构建读取文件，启动时同步到设备钥匙串；修改后重新编译即可更新。Release 不复制开发凭据。原工程上一级 `key` 目录仍保留兼容读取。
4. 也可以在「数据 → 设置」填写自己的密钥。联网部分仅调用 `https://api.deepseek.com`。默认模型为 DeepSeek Pro（`deepseek-v4-pro`），开启 thinking，推理强度为 `max`；可在设置修改模型。旧版 Flash 默认值首次升级为 Pro，之后用户主动选定的模型会保留。

没有 XcodeGen、CocoaPods 或 npm 安装步骤。全部运行依赖已随源码或资源提供；`iztro` 在构建前已打成 JavaScriptCore 可执行的本地 bundle，应用运行时不带 Node/Python。

首次克隆后可运行 `git config core.hooksPath .githooks` 启用提交检查；也可手动执行 `python3 Scripts/check_secrets.py --staged`。检查读取暂存区，阻止密钥文件或凭据值被提交，错误信息只显示文件名。构建产物、Python 缓存及图标探索的重复 ZIP 导出包不纳入 Git。

## 使用流程

在对话里提出具体问题 → 选择适用方法 → 自动弹出统一问事资料表 → 在同一页选择人员、填写全部资料及必要报数 → 点击“确认资料并开始” → 完成必要抽牌或六爻投掷 → 本地逐项计算 → 流式中文解读。提交表单后直接继续，不再逐项对话收集资料，也不再发送第二轮汇总确认。普通追问仍沿用当前盘面，不打开新表单。

每位参与人的姓名、姓/名拆分、生日、时刻、性别、出生地及当前所在地在同一张表中展开。日期与时间使用原生选择器，性别使用菜单，出生地和当前所在地的时区使用可搜索中文城市、地区或 IANA 名称的完整时区选择器。用户无需手写时区标识；已有资料自动带入，未知字段可以保留未知。

必填资料缺失会在同一页集中提示，表单保持打开，不开始计算。混合推演会事先列出可用部分、缺项和未采用方法。关闭表单会将未提交草稿留在当前问事中，可以从聊天中的“填写问事资料”继续；草稿不写入永久人员资料，最终确认后再按保存选择留存。

明确要求必须使用某种方法时，缺少其必要资料就停留在说明与补充阶段，不改用其他方法代算。允许部分输出的情况会先说明限制，例如八字时辰未知时只保留前三柱；混合解读可跳过不可用的方法或人员，最终解读末尾会说明缺少哪些资料、哪些方法未能提供参考。解读出现明显分歧时只提供两个选项；选择只会小幅改变个人解读偏好，不代表方法被证实或预测准确率。

塔罗作为独立本地方法，使用完整 78 张牌、正逆位与固定牌阵。牌名和牌义保留英文，DeepSeek 依据本次实际抽牌结果生成中文解读。抽牌和六爻结果连同输入快照保存在本机；继续未完成的交互、重新打开历史或再次请求解读不会重新抽取。当前聊天已有可用结果时，卦象细节、建议理由和后续追问默认沿用原盘，不再要求六掷或抽牌；只有明确要求重新起卦、重新抽牌或换一个问题时才准备新的推演。

DeepSeek 请求统一提供 65,536 token 输出预算，包含推理与最终回答；请求超时为 300 秒，资源总超时为 900 秒。聊天仅显示最终回答，模型返回的 `reasoning_content` 不解码、不保存、不展示。

「数据」独立保存每种方法的盘面、规则线索、限制、版本与计算耗时。留存人员完整平铺展示，每个人都可直接编辑或删除，不截断为前几份档案。基础资料单独保存，修改资料不会改写旧记录的输入快照。为他人问事会使用独立资料，不会自动套用本人的生辰。出生地旁可点“使用当前位置”，主动将定位得到的地点、坐标与当地时区填入出生地；当前所在地的定位入口独立填写当前信息，两者互不覆盖。

推演记录的最近列表与全部列表均可点右侧垃圾桶删除，确认后永久移除该次推演及原始结果。对话正文、留存人员和偏好保留，相关对话会标注“推演记录已删除”，不再提供查看或重试入口；删除正在处理的记录会停止对应任务，避免迟到结果重新出现。

处理进度默认折叠，只显示当前步骤；展开后可查看这次任务的完整步骤、执行状态与耗时，包括准备计划、逐项本地计算、综合解读和输出整理。进行中的步骤使用持续旋转的原生指示器，文字和计时更新时保持旋转；等待用户、完成、失败与停止分别显示对应状态。步骤由实际开始与完成事件推进，不展示模型的隐藏推理。聊天记录在独立区域内滚动，底部输入区使用不透明背景。

对话左上角的两横按钮打开历史侧栏，点击任意会话可以继续之前的对话，长按可删除该聊天；基础资料和独立推演记录仍保留。旧版本保存的对话归档会自动导入历史。先知回复下方的「翻看数据」直接打开该条回复所对应的各方法原始结果，无需在全部推演记录中查找。

## 多人档案与联合问事

每个人只需使用姓名识别，不必填写“本人、朋友、伴侣”等称谓。可以一次提供多人资料，也可以分轮补充，例如先说“张三，男，1995年1月2日出生；李四，女，1996年3月4日出生”，再说“张三出生时间08:30，出生地北京”。未在这次消息中提供的字段保留原值，出生地不会自动推断出生时区，未提供或明确不确定的出生时刻、时区继续保留未知状态。

已保存人员可一起参与同一问题；每次问卦保存参与人员及其当时的资料快照，后续修改档案不会改写历史结果。只有“我叫张三”或“我是张三”这样的直接声明才能建立可选的本人绑定，不会自动把第一份档案当作本人。同名人员有独立编号，姓名产生歧义时先确认具体档案，不按先后顺序覆盖。

结构化资料提取也要经过本地逐字段核验：模型没有得到本条消息明确支持的日期、时间、性别、出生地或时区，均不写入。旧版逐项答复保留解析兼容；新的资料收集通过统一表单完成，多人的省略称呼不会被擅自猜测。姓名五格需要分开确认姓氏和名字，例如“张三姓氏：张，名字：三”，不会从统一姓名自动拆分；改名后旧拆分失效，需重新确认。永久档案独立保存，聊天压缩和切换不删除人员资料。

## 计算范围

| 插件 | 已实现 | 当前边界 |
|---|---|---|
| 八字 | 四柱、十神、藏干、纳音、五行计数、起运与大运 | 不把五行计数等同于旺衰、格局或喜用神；未知时辰/交节日保留候选 |
| 紫微 | 本地 iztro 2.6.3，十二宫、星曜、四化、大限、流年 | 需要已知生辰时区；未知时辰不安唯一命盘 |
| 六爻 | 铜钱/蓍草概率、可复现爻值、变卦、八宫、纳甲、世应、六亲六神、本地卦辞爻辞 | 基础纳甲盘；未实现完整伏神、取用与应期，标为部分结果 |
| 梅花 | 时间/报数、本互变卦、动爻、体用生克、本地卦辞爻辞 | 固定已声明取法，不覆盖所有外应/字占 |
| 奇门 | 按实际交节的时家拆补转盘、九宫天地干、九星八门八神 | 固定排法与已实现盘面；未实现完整格局断语，标为部分结果 |
| 小六壬 | 农历月日时六宫推算、逐步记录 | 固定六宫取法 |
| 称骨 | 本地年/月/日/时骨重、总重及历史评诗 | 固定资料版本；不是精密命理预测 |
| 姓名 | 本地63,696字康熙部首笔画、五格/三才、繁体候选、现代笔画备选表 | 简体转换有一对多歧义；变字形时标为部分结果；未全量古籍校勘，缺字拒绝猜测 |
| 占星 | 本地 Astronomy Engine C，星位、主要相位、行运、上升点与等宫制 | 1900–2100；等宫制，不宣称 Placidus；高纬度或未知资料时不伪造宫位 |
| 塔罗 | 本地 78 张牌、正逆位、固定牌阵、英文牌义和可复查抽牌输入 | 随机抽牌用于象征性解读，不代表观测到现实信息；AI 不补抽或改牌 |

详见 `Documentation/Plugins/`。中国历法对非东八区的交节/月历边界尚未逐地校准，插件会给出限制。算法测试验证代码与声明的取法，不验证术数预测现实的有效性。

## 工程结构

```text
App/             SwiftUI 入口、对话状态机
Core/            模型、具名目录、资料准备策略、对话答复解析、插件协议、持久化与偏好
Plugins/Native/  八个原生方法插件
Plugins/Sky/     紫微及占星插件
Services/        DeepSeek SSE、钥匙串、定位、宽松上下文压缩
Views/           两个标签、聊天确认、抽牌与投掷、完整人员列表、原始数据和设置
Resources/       本地数据、JS bundle、许可证、图标与水墨头像
Vendor/          固定版本的 MIT 历法与天文 C 源码
Tests/           算法、资料准备与逐项答复、交互与旧档案兼容、流式解析及可选真实 API 集成
UITests/         两标签、聊天资料确认、物理交互与人员列表用例
```

新增文件后运行 `python3 Scripts/generate_project.py` 更新工程；脚本不依赖第三方库。新增插件的方式见架构文档。

iPad 按 [Apple 的方向要求](https://developer.apple.com/documentation/uikit/uiviewcontroller/supportedinterfaceorientations)保留四个界面方向以支持多任务，iPhone 保持竖屏；修改归档配置后须重新 Archive 再上传。项目未使用 App Intents，Debug/Release 均用 `LM_SKIP_METADATA_EXTRACTION=YES` 跳过该[元数据任务](https://github.com/swiftlang/swift-build/blob/12ac09ae1e3e344ce4dc085ee79306b2ccecb3e9/Sources/SWBApplePlatform/AppIntentsMetadataTaskProducer.swift#L55-L57)；以后接入 App Intents 或快捷指令时应移除此设置。工程生成脚本保留当前开发 Team 默认值，也可通过 `DEVELOPMENT_TEAM` 环境变量覆盖。

## 测试

```sh
xcodebuild -project BlindOracle.xcodeproj -scheme BlindOracle \
  -destination 'platform=iOS Simulator,name=BlindOracle QA' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- \
  -parallel-testing-enabled NO test
```

进度 UI 测试使用 Debug 专用的 `--ui-testing-progress` 自动阶段夹具或 `--ui-testing-progress-paused` 固定阶段夹具，直接驱动与真实任务相同的步骤模型，无需联网即可验证折叠、完整步骤、阶段切换和底部输入区布局。

普通测试不发 API 请求。真实 API 测试需显式启用，使用合成档案，不使用个人资料：

```sh
BLINDORACLE_LIVE_SMOKE=1 python3 Scripts/generate_project.py
xcodebuild -project BlindOracle.xcodeproj -scheme BlindOracle \
  -destination 'platform=iOS Simulator,name=BlindOracle QA' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- \
  -only-testing:BlindOracleTests/LiveIntegrationTests test
python3 Scripts/generate_project.py
```

开发凭据在 Debug `.app` 内仅用于本机调试；不要分发 Debug 包。发布时使用 Release，并让用户在设置中保存自己的密钥。Release 验证应检查 App 内没有 `dev-key.txt`。

模拟器测试应保留 ad-hoc 签名，否则钥匙串可能因缺少签名身份拒绝读写；这不要求付费开发者团队。真机仍需选择自己的签名团队。

## 数据与资源

- 永久档案、推演记录、偏好和版本化会话历史独立保存。`conversation-history.json` 保存各聊天的原文、摘要、待补充/待确认的问事计划、交互草稿与当前会话 ID，旧单会话文件保留兼容快照。原子写入，启用 iOS 文件保护并排除自动云备份；无法解码的文件先复制为 recovery 备份。
- 原始聊天不删除；达到约 32k 估算 token、并积累至少 24 条新消息后，才生成延续摘要，保留最近 16 条。网络摘要失败时可以使用本地检索摘要。档案与原始推演永不参与压缩。
- 系统定位权限仅在点击定位按钮后申请。内置常用城市表可离线使用，也支持手填；定位快捷填写通过 Apple 地理服务查询地名与当地时区，失败时可重试或手动填写，不用设备时区代替地点时区。
- 本地试算开关可验证本地链路，规则摘要不会冒充模型回答。AI 解读请求失败时保留选择与结果，重试不会重新抽牌或投掷。
- 头像和图标由内置 imagegen 生成，最终文件保存在 Assets.xcassets；提示词记录见 `Documentation/asset-prompt.txt`。其余纸纹与视觉效果用 SwiftUI 原生绘制。

第三方许可证和上游版本随资源保存；未使用未确认许可的 tt-qimen 源码或 Python meihua 应用代码。应用自己的发布许可由项目所有者决定。
