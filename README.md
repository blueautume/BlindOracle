# 瞎子 · BlindOracle

一个以水墨宣纸为视觉语言的原生 SwiftUI iOS 应用。只有「对话」「数据」两个标签。十种方法在设备本地执行，固定的联网 Agent 负责选择适用插件、提出资料与交互需求、整合解读和回答追问。

当前版本：**3.0.12（Build 38）**。

每批修改提交前同时递增补丁版本和 Build，运行一次 `python3 Scripts/version.py` 即可同步版本配置。单一版本源为 `Configuration/Version.json`，工程生成脚本也从这里读取；构建和测试不会自动加版本。`python3 Scripts/version.py --check` 检查工作区同步状态，提交钩子用 `--check-staged` 检查暂存区相对 HEAD 的递增。首次克隆后使用 `git config core.hooksPath .githooks` 启用密钥及版本检查。

## 打开与运行

1. 用 Xcode 27.1 打开 `BlindOracle.xcodeproj`，选择 `BlindOracle` scheme。
2. 选择 iOS 17 或更高版本的模拟器运行。真机需在 Signing & Capabilities 选择自己的开发团队；本项目的 bundle identifier 保持为 `com.lihao.BlindOracle`。
3. Debug 与 Release 随包提供内置 DeepSeek 服务凭据，从 `Configuration/Secrets.local.json` 的 `deepseek_api_key` 或既有开发配置读取。只生成 `dev-key.txt`，沿用设备现有的 ThisDeviceOnly 钥匙串标识。配置规则见[本地与随包密钥](Configuration/README.md)。
4. 所有对话与解读统一通过内置 DeepSeek Agent 联网完成，固定使用 `deepseek-v4-pro` 和 max 思考。产品设置仅提供语言、口吻、资料备份等用户功能，不展示供应商、模型、密钥或网络模式。网络失败保留数据并允许重试，不提供替代解读。

没有 XcodeGen、CocoaPods 或 npm 安装步骤。全部运行依赖已随源码或资源提供；`iztro` 在构建前已打成 JavaScriptCore 可执行的本地 bundle，应用运行时不带 Node/Python。

首次克隆后可运行 `git config core.hooksPath .githooks` 启用提交检查；也可手动执行 `python3 Scripts/check_secrets.py --staged`。检查读取暂存区，阻止密钥文件或凭据值被提交，错误信息只显示文件名。构建产物、Python 缓存及图标探索的重复 ZIP 导出包不纳入 Git。

## 使用流程

界面默认跟随 iOS 的 App 语言，也可在「数据 → 设置 → 语言」选择简体中文或 English。新回复默认使用界面语言；用户也可明确指定本条回复用中文或英文。切换语言不修改旧聊天、人员档案或已保存的盘面和牌面。英文模式仍使用原有的国内地区目录和出生地时区规则；地区可用英文或拼音浏览。

在对话里提出具体新问题 → 选择适用方法 → 自动弹出统一问事资料表 → 在同一页选择人员、核对可提供的资料及必要报数 → 点击“确认资料并开始” → 完成必要抽牌或六爻投掷 → 本地逐项计算 → 流式解读。提交表单后直接继续，不再逐项对话收集资料，也不再发送第二轮汇总确认。

已有问事分为普通解释、补充推演和全新推演三路（`reply / supplement / intake`）。普通解释沿用当前结果；追问确需新能力，或相关资料与条件变化时，只补算新增或受影响的部分。同一方法、同一人员的相关输入及插件版本未变时直接复用，不因要求展开、提到方法名称或时间自然流逝而重复计算。补算缺资料才打开统一表单，已有输入有效时直接继续；明确重新起卦、重新抽牌或换一个问题仍走新推演流程。

每位参与人的姓、名、别名、性别、出生日期、出生时刻、出生地和当前所在地平铺在同一张表中，个人资料可留空。当前所在地下方显示只读八字原文，按出生地真太阳时在设备本地计算，随出生资料变化实时更新；正式八字推算使用同一算法。没有别名或可用姓名时显示稳定的四位档案代号。出生日期和时刻可以分开填写或清空。出生地和当前所在地都可从内置地区列表逐级选择，也可点字段旁的图标使用当前位置。选择地区可停在市一级，也可细化到区县。新资料默认使用北京时间。旧档案原有的有效时区会随资料带入。

内置地区目录的 3,633 条记录（含 3,248 个末级地区）均提供本地 WGS84 代表坐标，选择目录内地区无需联网补坐标。2026-11-06 补齐了 258 条区县末级和 7 条市级记录，保留原有名称、层级和已有坐标；来源、群岛范围及精度限制见 [地区数据说明](Resources/Locations/SOURCES.txt)。这些是地区代表点，不是具体出生地址，

可在表单内选取已保存的档案，已有资料会随档案带入。明确提及已存姓名时，应用也会在本地尝试匹配。只有一份档案且未指定他人时，会作为表单候选预填，仍由用户确认本次对象；不会因此自动建立“本人”绑定。同名或多份档案可在名单中选取。

咨询方法、术语或所需资料时先回答问题，不会因提到方法名就发起推演。表单按本次方法列出所需资料、可用部分及未采用的方法，排盘性别也随方法标明必填或可选。关闭表单会将未提交草稿留在当前问事中，可以从聊天中的“填写问事资料”继续；草稿不写入永久人员资料，最终确认后再按保存选择留存。表单及抽牌、投掷页均可明确取消本次操作；“稍后继续”保留进度。等待抽牌时也能在聊天中询问规则、取消或同题换方法，咨询不会丢失已选牌。

明确指定的方法缺少必要资料时，普通提交会停留在表单。若表单提供“改用小六壬”，可主动切换为对问题本身的参考。未指定必选方法且没有其他可执行方法时，表单会提示使用小六壬。允许部分输出的情况会先说明限制，例如八字时辰未知时只保留前三柱；混合推演可跳过缺资料的方法或人员，并说明原因。解读出现明显分歧时只提供两个选项；选择只会小幅改变个人解读偏好，不代表方法被证实或预测准确率。

塔罗作为独立本地方法，使用完整 78 张牌、正逆位与固定牌阵。牌名和牌义保留英文，联网 Agent 依据本次实际抽牌结果生成所选语言的解读。抽牌和六爻结果连同输入快照保存在本机；继续未完成的交互、重新打开历史或再次请求解读不会重新抽取。同一问事补算保留原起问时刻、随机种子、报数和已完成交互，明确说只用某种方法时，本次只保留所选方法，旧记录仍留存。已有塔罗或六爻不要求重做；新增塔罗或六爻且尚无有效保存选择时，才接着完成对应操作。补算会另存一份包含复用与新增结果的完整记录，再结合本条追问解读，历史原盘保持原样。

DeepSeek 请求提供 65,536 token 输出预算，包含推理与最终回答。请求超时为 300 秒，资源总超时为 900 秒。聊天只显示最终回答。

「数据」页将「留存资料」和「推演方法」作为同级分区，统一标题样式和卡片对齐。可管理留存人员，也可进入方法说明。留存人员完整平铺展示，点按资料行可编辑；左滑可直接删除，不再弹出确认提示。基础资料单独保存，修改资料不会改写旧记录的输入快照。撤回旧出生时刻后，后续解读会重新计算受影响的项目，按时辰未知的可用范围回答，不沿用旧时柱和大运。为他人问事会使用独立资料，不会自动套用本人的生辰。手动选择的地区即使暂时没有坐标也会保留。

处理进度默认折叠，只显示当前步骤；展开后可查看这次任务的完整步骤、执行状态与耗时，包括准备计划、逐项本地计算、综合解读和输出整理。进行中的步骤使用持续旋转的原生指示器，文字和计时更新时保持旋转；等待用户、完成、失败与停止分别显示对应状态。步骤由实际开始与完成事件推进，不展示模型的隐藏推理。聊天记录在独立区域内滚动，底部输入区使用不透明背景。

回答生成时仍能打开之前回复的“翻看数据”，也可停留在已滚动到的旧消息。回答生成时可以随时停止，也可以直接发送追问：应用会保留已输出的内容并开始处理新问题。切到其他应用时，解读会在 iOS 允许的后台时间内继续。如果停止、出错或被系统中断，可点输入框上方的「重试」，沿用已确认的资料、抽牌和本地结果。

对话左上角的两横按钮打开历史侧栏，点击任意会话可以继续之前的对话，长按可删除该聊天；基础资料和独立推演记录仍保留。旧版本保存的对话归档会自动导入历史。先知回复下方的「翻看数据」打开该次推演的盘面、规则线索、限制、版本和计算耗时。

## 多人档案与联合问事

多人问事可以在同一张表单中添加匿名档案或选择已有档案。也可以用明确姓名一次提供多人资料，或分轮补充，例如先说“张三，男，1995年1月2日出生；李四，女，1996年3月4日出生”，再说“张三出生时间08:30，出生地北京”。未在消息中提供的字段保留原值，缺失的出生时刻可以继续留空。

已保存人员可一起参与同一问题；每次问卦保存参与人员及其当时的资料快照，后续修改档案不会改写历史结果。只有“我叫张三”或“我是张三”这样的直接声明才能建立可选的本人绑定，不会自动把第一份档案当作本人。同名人员有独立编号，姓名产生歧义时先确认具体档案，不按先后顺序覆盖。

结构化资料提取也要经过本地逐字段核验：模型没有得到本条消息明确支持的日期、时间、性别、出生地或时区，均不写入。英文问题中明确提供的姓名、性别和连续的出生日期、AM/PM 时间、出生地会在资料确认表内预填；工作地点、其他人的资料及否定或不确定的出生陈述不会作为该出生语句的依据。区县出生地保留逗号分隔的城市、省份和国家，完整层级唯一匹配内置地区目录时带入区县编号及目录坐标；同名区、矛盾层级或国家不能靠截短文本自动选择。支持 24 小时时刻、AM/PM、noon 和 midnight，保留明确提供的秒数；无 AM/PM 的歧义时刻保持待确认。未提供出生时区时，表单沿用北京时间默认值，保留当地日期与钟表时间，不把默认值当成用户明确提供的事实。旧版逐项答复保留解析兼容；新的资料收集通过统一表单完成，多人的省略称呼不会被擅自猜测。姓名五格需要分开确认姓氏和名字，例如“张三姓氏：张，名字：三”，不会从统一姓名自动拆分；改名后旧拆分失效，需重新确认。永久档案独立保存，聊天压缩和切换不删除人员资料。

| 梅花 | 时间/报数、本互变卦、动爻、体用生克、本地卦辞爻辞 | 固定已声明取法，不覆盖所有外应/字占 |

| 小六壬 | 农历月日时六宫推算、逐步记录 | 固定六宫取法 |
| 称骨 | 本地年/月/日/时骨重、总重及历史评诗 | 固定资料版本；不是精密命理预测 |

## 工程结构

```text
App/             SwiftUI 入口、对话状态机
Core/            模型、档案目录、资料准备策略、对话答复解析、插件协议、持久化与偏好
Plugins/Native/  八个原生方法插件
Plugins/Sky/     紫微及占星插件
Services/        模型请求与 SSE、钥匙串、定位、宽松上下文压缩
Views/           两个标签、聊天确认、抽牌与投掷、完整人员列表、原始数据和设置
Resources/       本地数据、JS bundle、许可证、图标与水墨头像
Vendor/          固定版本的 MIT 历法与天文 C 源码
Tests/           算法、资料准备与逐项答复、交互与旧档案兼容、流式解析及可选真实 API 集成
UITests/         两标签、聊天资料确认、物理交互与人员列表用例
```

新增文件后运行 `python3 Scripts/generate_project.py` 更新工程；脚本不依赖第三方库。新增插件的方式见架构文档。

iPad 按 [Apple 的方向要求](https://developer.apple.com/documentation/uikit/uiviewcontroller/supportedinterfaceorientations)保留四个界面方向以支持多任务，iPhone 保持竖屏；修改归档配置后须重新 Archive 再上传。项目未使用 App Intents，Debug/Release 均用 `LM_SKIP_METADATA_EXTRACTION=YES` 跳过该[元数据任务](https://github.com/swiftlang/swift-build/blob/12ac09ae1e3e344ce4dc085ee79306b2ccecb3e9/Sources/SWBApplePlatform/AppIntentsMetadataTaskProducer.swift#L55-L57)；以后接入 App Intents 或快捷指令时应移除此设置。工程生成脚本保留当前开发 Team 默认值，也可通过 `DEVELOPMENT_TEAM` 环境变量覆盖。

## 测试

```sh
xcodebuild -project BlindOracle.xcodeproj -scheme BlindOracle \
  -destination 'platform=iOS Simulator,name=BlindOracle QA' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- \
  -parallel-testing-enabled NO test
```

进度 UI 测试使用 Debug 专用的 `--ui-testing-progress` 自动阶段夹具或 `--ui-testing-progress-paused` 固定阶段夹具，直接驱动与真实任务相同的步骤模型，无需联网即可验证折叠、完整步骤、阶段切换和底部输入区布局。

普通测试不发 API 请求。真实 API 测试需显式启用，使用合成档案，不使用个人资料：

```sh
BLINDORACLE_LIVE_SMOKE=1 python3 Scripts/generate_project.py
xcodebuild -project BlindOracle.xcodeproj -scheme BlindOracle \
  -destination 'platform=iOS Simulator,name=BlindOracle QA' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- \
  -only-testing:BlindOracleTests/LiveIntegrationTests test
python3 Scripts/generate_project.py
```

授权分发的 Release 包包含内置凭据。检查包资源时核对 `dev-key.txt`，确认没有遗留的其他服务资源；核对过程不打印密钥值。具体导入与轮换规则见[配置说明](Configuration/README.md)。

安装包中的内置密钥可被提取，仅用于本次明确授权的分发，不能对安装包接收者保证密钥保密。

开发验证通过受控测试读取内部连接元数据，检查固定请求模型、实际模型、思考强度及输出预算。连接诊断不出现在产品设置中。真机未测试时，不依据模拟器结果宣称已诊断手机。

模拟器测试应保留 ad-hoc 签名，否则钥匙串可能因缺少签名身份拒绝读写；这不要求付费开发者团队。真机仍需选择自己的签名团队。

## 数据与资源

- 永久档案、推演记录、偏好和版本化会话历史独立保存。`conversation-history.json` 保存各聊天的原文、摘要、待补充/待确认的问事计划、交互草稿与当前会话 ID，旧单会话文件保留兼容快照。原子写入，启用 iOS 文件保护并排除自动云备份；无法解码的文件先复制为 recovery 备份。
- 补算记录完整复制复用结果，不依赖源记录才能恢复；`OraclePlan.baseRunID/followUpQuestion`和`OracleRun.reusedResultIDs`保留来源、补充问题及复用标记。新增字段可缺省读取，兼容旧JSON记录。
- 原始聊天不删除；达到约 32k 估算 token、并积累至少 24 条新消息后，才生成延续摘要，保留最近 16 条。网络摘要失败时保留原摘要和完整消息。档案与原始推演永不参与压缩。
- 内置地区列表及其代表坐标均可离线读取。只有在用户点击出生地或当前所在地的定位按钮时才申请系统定位权限，定位使用设备坐标，新资料使用北京时间。
- 发布版本没有本地解读或网络模式开关。解读请求失败时保留选择与计算结果，重试不会重新抽牌或投掷。Debug 专用确定性 Agent 夹具仅供自动化测试，不能由用户偏好启用。
- 历史侧栏支持确认后一键清空全部对话、摘要和未完成草稿；人员档案、偏好与独立推演记录保留。流式输出中仍可翻看已有推演数据。
- 进入后台会保存当前已接收的回答；重启后保留部分正文和本地结果，并结束上次中断的进度。历史中的单个会话损坏时尽可能恢复其他会话；恢复副本无法保存时阻止覆盖原文件。稳定性改动与后续计划见 `Documentation/Architecture.md` 第 9 节。
- 头像和图标由内置 imagegen 生成，最终文件保存在 Assets.xcassets；提示词记录见 `Documentation/asset-prompt.txt`。其余纸纹与视觉效果用 SwiftUI 原生绘制。

第三方许可证和上游版本随资源保存；未使用未确认许可的 tt-qimen 源码或 Python meihua 应用代码。应用自己的发布许可由项目所有者决定。
